# Buildathon operator runbook

Use [operations](operations_phase06.md) and [pitch](pitch_phase06.md). The built
React frontend and backend share one loopback origin, with no Vite dev server.
Required notices: MOCK_AI - CANNED DEMONSTRATION; SYNTHETIC SECURITY EVALUATION;
NOT VERIFIED LIVE IMAGE EXTRACTION. Source badges and canned model IDs stay visible.

Before presenting: verify readiness; open separate browser contexts for manager,
contractor, agent, engineer A and independent engineer B using private random
credentials. Never display passwords, bearer headers, the operator token or a
challenge-bearing screen in shared screenshots. Keep the contractor session active
through manager review; logout invalidates its challenge and current approval.

Business live actions: manager creates/assigns a fictional PUMP-042 job/case;
contractor issues challenge and uploads fictional PNG; canned unsafe reading
produces SAFETY_ALERT/L1; manager rejects to L0; contractor uses a fresh challenge
and different bytes to reach canned L2; agent prepares invoice; manager confirms
exact current binding to L3; agent records simulated completion and receipt;
review persisted audit. No physical equipment or money is controlled.

Engineering live actions: A creates/runs weak candidate against fixed independent
labels; inspect real A02 false approval and finding; gate BLOCKED. A creates/runs
safe candidate and proposes remediation. B independently reviews exact candidate/
run/corpus and gate becomes READY_FOR_MANUAL_RELEASE, published=false. No policy
is automatically registered, rewritten or deployed. A proposal alone proves no fix.

Open the completed run detail before its finding: the metrics screen explicitly
shows SYNTHETIC SECURITY EVALUATION and binary denominators. Weak candidate:
1/26 false approvals, 0/6 false rejections and one separate review bypass; safe
candidate: 0/26 and 0/6, 38/38 scenarios passed. These are fixed fictional policy
tests. The Phase 06 evidence includes a supplementary read-only browser capture
of the actual stored weak run; it is not a fourth new regression execution.

Starting state in fresh rehearsals consists only of provisioned fictional accounts
and image fixtures. Business state, manager decisions, regressions and gates are
generated by actual browser actions. For a short talk, an already executed safe
run may be loaded as a fallback only if described as **previously executed
SYNTHETIC regression**, with its persisted IDs/hash. Never call stored output live.

Suggested 180-second cue budget appears in pitch. Automated visual action timing
does not measure a human's spoken delivery. Three standalone Chromium rehearsals
record UTC start/finish, each step and API duration, authoritative observations,
screenshots and safe references. Run them with the supplied rehearsal driver after
packaging; it is not pytest rerun three times. Final measured numbers are in the
Phase 06 report. A human narrated rehearsal remains required before public judging.

If a run is slow, retain the pending/failed state; show the independently recorded
earlier result, label provenance and explain the 20-second worker deadline. If a
browser/API fails, do not pretend completion: refresh current state, preserve
audits, use exact replay if eligible or start a fresh isolated root. Never delete
the normal DB, reset the Gemini marker, switch model or trigger live inference.

Closing checklist: safe gate unpublished; receipts simulated; source notices
visible; three timings genuinely recorded; no credentials in evidence; graceful
Stop verified; backups/evidence preserved. Cloud/remote status remains unattempted.

Standalone command after the reviewed native package build, from frontend:

```powershell
node rehearsal/run.mjs --package ../.venv/phase06-native-rehearsal.zip --runs 3
```

Use --headed only when a visible browser is wanted. Default is explicitly labeled
headless visual-action measurement, not a human spoken performance. Private raw
results remain in the printed ignored root; share only reviewed redacted evidence.

Measured three fresh packaged workflows: 20.882s, 20.350s and 19.795s total,
including startup, ordinary restart, negative checks, graceful stop and backup.
Pitch-only visual actions were 11.695s, 11.756s and 11.359s. No action exceeded
its recorded budget and no unexpected browser errors occurred. Keep the full
180-second narrated cue plan; do not infer human delivery from automated speed.
